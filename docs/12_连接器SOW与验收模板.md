## 1. 项目名称

`<客户名称> 单工位质检-MES 可靠连接器试点`

## 2. 项目目标

在约定工位、产品族、工单类型和 MES 接口范围内，完成：

- 标准化质检结果接入；
- SQLite Outbox 持久化；
- MES 开单/报工调用；
- 有效回执校验和 UA 写回；
- 断网、超时、重复消息、重启恢复和死信人工处置；
- 逐笔回执对账。

本项目不包含视觉识别准确率验收。视觉增值能力使用独立 SOW。

## 6. 验收口径

### 6.1 功能验收

1. 合法质检事件能够写入持久化 Outbox；
2. 网络正常时完成 MES 调用和回执写回；
3. NG 开单和完工报工分别落到正确回执字段；
4. 回执不覆盖派工工单号；
5. 相同幂等键重复提交不产生重复业务效果；
6. 同键不同载荷被拒绝并可审计；
7. 4xx 不重试并进入死信；
8. 429 按 `Retry-After` 退避；
9. 5xx/timeout 有界重试；
10. 非法 2xx 不写 UA 回执；
11. 死信可查询、确认和人工重放；
12. 通过 `correlationId` 可串联来源事件、队列、MES 请求、MES 回执和 UA 写回。

### 6.2 故障验收

| 场景 | 预期 |
|---|---|
| 网络中断 10 分钟 | 任务保留，恢复后继续投递 |
| MES 超时 | 使用同一幂等键重试 |
| MES 5xx | 有界退避，超限死信 |
| MES 4xx | 终止，不重试 |
| MES 429 | 遵守 `Retry-After` |
| 重复提交 | 不重复入队 |
| 发送中进程崩溃 | 租约过期后恢复 |
| 回执后 UA 写回前崩溃 | 重启后继续写回 |
| 非空队列重启 | 队列不丢且状态可恢复 |
| 磁盘满 | 停止接收或进入明确错误状态，不静默丢失 |
| 时钟漂移 | 拒绝超范围时间戳并告警 |

### 6.3 验收标准

- 约定故障矩阵全部通过；
- 回执与 MES 日志逐笔一致；
- 没有未解释的重复业务单；
- 每个死信有原因、状态和人工处置入口；
- 不存在仅依赖 Node-RED 内存或 flow context 的权威队列状态。
