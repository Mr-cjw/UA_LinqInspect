## 2. 推荐演示顺序（10 分钟）

### 0:00–1:00 先讲问题

> 工厂不缺“看见缺陷”的模型，缺的是缺陷被发现之后，结果能不能可靠进入 MES。MES 会超时、网络会断、设备会重启；如果没有持久化、幂等、重试、死信和回执对账，就会漏单、重复开单，最后靠人工对账。

### 1:00–3:00 `/vision`：先证明 AI 入口是真的

1. 选择一个 NG 样本（划痕、凹坑、污渍或缺件）。
2. 指出图像质量门禁：分辨率、亮度、对比度、清晰度、过曝/欠曝。
3. 指出模型输出：缺陷类别、置信度、五类概率分布、推理耗时。
4. 打开模型卡，主动说明：训练/验证图像是合成的，指标不是现场精度；低置信度转人工复核。

预期结果：页面显示 `NG` 或 `REVIEW`，并给出类别、置信度和概率分布。

### 3:00–7:00 `/overview`：跑完整业务闭环

点击“现场运行演示”，不要提前录屏。运行期间说明：

> 这不是视频。左边是本地视觉模型和真实 Edge Core API、SQLite Outbox、Worker；右边是同级设备上下文项目启动 Mock PLC，采集状态、产量、温度和报警。MES 和 OPC UA 写回是本地模拟。

结果出来后按顺序讲：

1. `DONE`：只有 MES 回执和 UA 写回都确认，任务才结束。
2. `MES-JX-DEMO-0001`：同一个业务键不会重复形成业务结果。
3. OEE：Availability / Performance / Quality 都能下钻到来源。
4. RCA：温度异常只是时间窗候选原因，不是因果证明。
5. 审计：失败、重试、死信、重启和人工重放都有轨迹。

### 7:00–9:00 `/joint`：解释“损失发生在哪里”

只讲三件事：

- 视觉 NG 与设备停机/温度异常在同一时间窗对齐；
- 质量结果进入 MES 的同时，设备上下文解释 OEE 损失；
- 两个项目通过业务键、correlationId 和时间线关联，不是两张互不相干的报表。

### 9:00–10:00 收边界和下一步

> 今天没有真实相机、客户样本、真实 PLC 和真实 MES，所以这不是生产验收。下一步是单工位付费验证：真实相机和 300 件样件、真实 MES 沙箱、72 小时影子运行、逐笔对账，再决定是否扩站。

## 4. 现场失败时怎么办

先说明失败的是演示环境，不冒充成功，再按顺序排查：

1. 端口是否被占用：换 `--port 8900`。
2. 同级 `rpi4-opcua-oee-rca-gateway` 是否存在，是否执行过 `npm install`。
3. `node --version` 是否可执行。
4. Python 是否安装 `numpy` 和 `Pillow`。
5. 终端是否有 Mock PLC 或 OPC UA 连接错误。

如果 2 分钟内修不好，直接切到 `交付材料/演示/` 里的 PDF 和完成态截图，并明确说“这是刚才本地跑通的证据，现场环境现在有问题”。

## 5. 回答口径

### 这是不是 AI 质检？

是。AI 质检是业务入口；当前视觉训练/验证图像是合成的，证明的是推理、质量门禁和业务闭环，不是现场精度。

### 没有硬件凭什么证明？

硬件没到之前，最值钱的是软件可靠性：结果不丢、不重、可对账、可追溯。相机到位后换采集层和模型，不推翻已验证的底座。

### 壁垒在哪里？

不是 OPC UA 或 YOLO 本身，而是现场故障样本、MES 适配器、事务状态机、回执审计、部署验收工具和跨客户复用。

### 现在最需要什么？

一笔小额验证资金：一台工业相机、镜头/光源/工装、300 件真实样件、一个 MES 沙箱，跑通单站验收，再谈规模化。

### 为什么不是又一个视觉公司？

视觉是入口；我们做的是缺陷结果进入 MES 的可靠交付、回执对账和设备上下文，可以接不同视觉前端。

### 为什么现在投？

用 1～2 万小额验证资金锁定真实相机、样件和 MES 沙箱，低成本拿到可复现结果后再决定规模化；不先铺整线、不压库存。

## 6. 不要说的话

- 不说“已经完成生产集成”。
- 不说“视觉已经完成生产验收”。
- 不把合成数据准确率说成现场精度。
- 不说“零漏检”或“exactly-once”。
- 不把模拟 MES 说成客户 MES。
- 不把 RCA 时间重合说成因果证明。
- 不把针对某个人或某次会面的页面当成标准产品。
