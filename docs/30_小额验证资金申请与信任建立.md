# 小额验证资金申请与信任建立：先让能力接受验证，再谈预算

> 日期：2026-11-22 ｜ 适用阶段：软件可运行、无客户案例、需要真实产线证据
>
> 结论先行：**不要一开口申请“投资”，先申请一笔 1～2 万元、可报销、可分阶段停止的验证预算；达标后再追加到 3～5 万元。** 对方不是在买一个故事，而是在用最小代价判断：这个痛点是否真实、这笔钱是否可控、团队是否值得继续合作。
>
> 对外一页 PDF：运行 `python3 scripts/render_validation_budget.py`，输出到 `.tmp/investor-deck/小额验证资金申请_一页版.pdf`。

## 0. 先让能力说话，再谈预算

不要用话术替代能力。第一次见面最有效的做法，不是背一段更漂亮的开场，而是把项目交给对方出题：

> **“您指定一个故障场景，我现场跑给您看。跑完您把日志和回执带走，找懂技术的人核。如果这条链路经不起您出的题，我就不该拿这笔钱。”**

### 0.1 让对方挑一项现场验证

| 对方出的题 | 项目应该现场证明什么 | 业务语言 |
|---|---|---|
| MES 超时 | NG 进入本地事务队列，重试后仍能拿到回执 | 这条 NG 不会因为 MES 忙就静默消失 |
| 断网/进程被杀 | 服务重启后继续处理，业务键和审计时间线保持 | 换班、重启、断网后还能对上同一笔账 |
| 重复上报 | 同一业务键不重复形成业务结果 | 同一条 NG 不会开两次单 |
| 图像质量不合格 | 门禁拦截并转人工复核，不自动放行或开单 | 图看不清时系统不猜，不拿错误结果进 MES |
| 证据复核 | 导出业务键、回执、日志、模型/图像哈希和审计链 | 结果不是一张截图，第三方可以复核 |

让对方自己选，不要只挑最简单的一项。能力如果只能跑通顺场景，就不能支撑真实产线。

### 0.2 通过后再谈钱

顺序应该是：

1. 先看现有软件和现场演示；
2. 对方指定一个失败场景，现场复现；
3. 对方带走原始日志和证据，自行核验；
4. 认可能力后，再谈 1～2 万元验证预算；
5. 用这笔钱补真实相机、真实 MES 和真实产线证据，而不是补“软件是否存在”。

如果现场测试不通过，直接承认并停止，不用话术把失败说成成功。**能力验证失败后还继续要钱，比一开始被拒绝更伤信任。**

### 0.3 表达的正确位置

话术只负责三件事：约到一次验证、把测试条件说清楚、把失败边界写下来。它不能负责把没有的能力说成有，也不能替代日志、回执和现场结果。

## 1. 先改变请求的性质

“给我 5 万做项目”会让对方承担一个模糊、无法中途退出的风险。更可信的请求是：

> **先批 1～2 万元验证预算，只买一台适配产线的工业相机、一个边缘算力盒和必要的镜头/光源/线缆。先在现有软件上跑通一个真实工位的质检-MES 对账闭环；达不到约定条件就停止，不追加。**

这不是文字游戏，而是把对方的决策拆小：

| 普通项目请求 | 验证预算请求 |
|---|---|
| 先给 5 万，做完再说 | 首笔 1～2 万，达标再追加 |
| 钱用于开发、差旅、人工 | 钱只用于可盘点硬件和现场验证 |
| 失败后钱花完 | 失败即停，余额退回，硬件保留 |
| 靠汇报证明进度 | 靠原始日志、发票、视频和验收报告 |
| 先谈估值和股权 | 先不谈股权，验证成功后再谈合作条款 |

对做金融的人，最重要的不是“你说项目多好”，而是：**最坏情况下他损失什么、什么时候可以停、停下来还能留下什么。**

## 2. 让对方相信的五件事

信任不是一句“请相信我”，而是五件可以检查的事：

1. **已经做出来的东西**：现有视觉推理、图像质量门禁、SQLite Outbox、MES 回执、故障恢复和本地演示已经可运行，不是从零开始。
2. **钱花在哪里**：相机、镜头/光源、边缘盒、线缆和少量现场耗材，逐项报价、发票和资产清单。
3. **失败怎么处理**：每个阶段有停止条件；不达标不追加；未使用余额退回；硬件归属提前写清。
4. **结果怎么核验**：每周一页进展、原始日志、测试视频、发票和可复跑命令；对方可派人到现场。
5. **你自己投入什么**：现有软件、自己的时间、现有演示设备和现场协调；验证期不领额外项目工资，或只报销必要成本。

这五件事合起来，才叫“低风险验证”。只说“AI 市场很大”或“给我钱我就能做出来”，反而会降低信任。

## 3. 1～5 万元怎么花

首期不做全量硬件铺陈，只做一个工位的最小采集与边缘计算组合。以下为预算假设，实际以现场报价为准：

| 项目 | 建议预算 | 说明 |
|---|---:|---|
| 高清工业相机 | 3,000～12,000 元 | 一台，接口和分辨率按产品与节拍选型；优先借用/租赁测试 |
| 镜头、光源、支架、线缆 | 2,000～8,000 元 | 先满足一个工位，不做整线 |
| 边缘算力盒 | 3,000～10,000 元 | 本地推理、Outbox、日志和演示服务 |
| 现场安装与耗材 | 1,000～5,000 元 | 线缆、转接、固定件、必要差旅 |
| 不可预见费 | 1,000～5,000 元 | 只在双方确认后使用 |
| **合计** | **约 1～4 万元** | 首笔建议 1～2 万元，达标后再追加 |

原则：

- 不买整线设备，不压库存，不做与验证无关的硬件；
- 能借则借、能租则租，必须买时保留发票和资产编号；
- 硬件归属、保管人和处置方式在付款前写清；
- 不把预算用于工资、招待、办公室或与验证无关的软件订阅。

## 4. 分阶段拨款，而不是一次给满

### 阶段 0：零成本现场确认（0 元，1～2 天）

先不买硬件，确认五件事：

- 一个产品族、一个质检工位、一类主要缺陷；
- 现有质检方式和节拍；
- MES/ERP 接口、字段样例和测试环境；
- 谁提供数据、谁签字验收、谁维护现场；
- 现场是否允许拍照、录像和脱敏留样。

如果这五件事无法确认，**不建议花第一笔钱**。这不是项目失败，而是避免把预算花在错误现场。

### 阶段 1：台架/离线验证（首笔 1～2 万元，1～2 周）

只做：

- 相机、镜头/光源、边缘盒到位；
- 对约定样本做采集、图像质量门禁和本地推理；
- 用历史样本或模拟 MES 跑通 NG 入队、重试、死信、回执和审计；
- 形成一份可复现的离线验证记录。

进入下一阶段的条件：

- 图像质量可稳定判读；
- 约定类别有可测量的类别级指标；
- NG 事件可追溯、可重放；
- 对方确认继续，才申请第二笔。

### 阶段 2：真实单站闭环（追加 1～3 万元，2～4 周）

只做：

- 接入一个真实工位和一个 MES 测试接口/沙箱；
- 跑通真实质检事件到 MES 回执的对账；
- 做断网、MES 超时、进程重启和重复消息演练；
- 形成验收报告、原始日志、视频和资产清单。

任何阶段不达标，停止追加，不用“再给一点钱就能成”来延长项目。

## 5. 什么才算“跑通”

“跑通”不是演示一次成功，而是在约定范围内可重复。建议在花钱前把验收口径写成一页：

| 维度 | 建议验收口径 |
|---|---|
| 场景 | 一个产品族、一个工位、一类缺陷、一个 MES 接口 |
| 样本 | 不少于 300 件或覆盖 3 个班次，具体由现场确定 |
| 视觉 | 类别级 Precision/Recall、图像质量门禁通过率、人工复核比例 |
| 交付 | NG 事件投递成功率、重复业务单数量、MES 回执对账一致率 |
| 恢复 | 断网、MES 超时、重启后的恢复时间和数据完整性 |
| 证据 | 原始日志、业务键、回执号、视频、模型版本和测试命令 |

必须提前说清：

- 不承诺零漏检、零漏单或 exactly-once；
- 合成数据指标不等于现场精度；
- 本地模拟 MES/PLC 不等于客户生产验收；
- 目标值由双方在启动前确认，未达标就不称为“跑通”。

## 6. 资金管理让对方放心

建议主动提供：

- 单独台账：日期、用途、金额、发票、经手人；
- 资产清单：相机、镜头、光源、边缘盒的编号、保管人和归属；
- 每周一页：本周做了什么、花了多少、遇到什么、下周计划；
- 原始证据：日志、截图、视频、测试命令，不只发总结；
- 停止机制：未达标即停，余额退回，硬件按约定保留或归还；
- 变更机制：超出原范围的需求，先报价再决定，不先做后要钱。

如果对方愿意，最好让他指定一个财务或技术联系人共同核对。**让第三方能查，比让本人相信更有用。**

## 7. 第一次沟通怎么开口

### 7.1 30 分钟议程

1. 5 分钟：说明“我不是来要投资，是申请一笔可停止的验证预算”；
2. 10 分钟：用现有软件演示一条 NG 从发现到 MES 回执的链路；
3. 5 分钟：主动说最坏情况、停止条件和余额/硬件处理；
4. 5 分钟：给出 1～2 万首笔预算和分阶段计划；
5. 5 分钟：确认他最担心什么、是否愿意派人去现场。

### 7.2 开场话术

> 您先不用判断要不要投这个项目。您只需要判断三件事：这个质检到 MES 的痛点是否值得花 1～2 万验证；这笔钱是否花得透明；如果失败，能不能及时停。
>
> 我不申请全量硬件，也不要求一次给 5 万。第一笔只买一台工业相机、一个边缘盒和必要的光源线缆，在现有软件上跑一个真实工位。硬件归您或公司，发票和资产清单给您；未用完的钱退回。
>
> 如果现场没有 MES 接口、没有数据、没有负责人，我会建议不花这笔钱。达到阶段目标后，我再申请第二笔；达不到就停。

### 7.3 主动说最坏情况

> 最坏情况是：现场图像质量不达标、MES 接口拿不到、或者客户不愿意配合，导致验证无法完成。出现这种情况，我们停止，不追加预算，把未使用余额退回，硬件保留；同时给您一份失败原因报告。这样您损失的是可控的验证成本，而不是一个无底洞。

## 8. 他可能会问什么

| 他会问 | 不要这样答 | 建议这样答 |
|---|---|---|
| 我凭什么相信你 | “我一定能做成” | “不凭这句话。现有软件和演示可以先看；钱分阶段、买可盘点硬件、失败即停，您还可以派人到现场核验。” |
| 5 万够吗 | “差不多够” | “首笔只要 1～2 万；不够时按阶段目标再申请，不一次给满。” |
| 失败了怎么办 | “不会失败” | “失败就停，余额退回，硬件保留，给您失败原因报告。失败也是验证结果。” |
| 为什么不让工厂出钱 | “工厂没钱” | “工厂愿意出最好；不愿意出，说明需求或预算还没验证。这笔小钱是买证据，不是替工厂做免费改造。” |
| 你会不会拿钱做别的 | “不会” | “专款专用、发票、资产清单、周报；您可以指定联系人共同核对。” |
| 你没有客户案例 | “很快就有” | “对，所以我不按规模化项目要钱，只申请验证预算。没有案例就用可核验的现场证据换下一步。” |
| 我要不要占股 | “都可以” | “先不谈股权，避免在证据不足时定价。验证成功后再按双方财务/法务确认的条款谈合作。” |
| 多久能看出来 | “很快” | “阶段 0 两天，阶段 1 一到两周，阶段 2 两到四周；每个阶段都有停止条件。” |

## 9. 信任的底层公式

对方愿意给钱，通常不是因为被说服，而是因为同时看到了：

> **可信度 + 透明度 + 可控性 + 可验证性 + 个人投入**

- 可信度：现有软件、测试、演示和真实边界；
- 透明度：预算、发票、资产、日志和失败原因；
- 可控性：首笔小额、阶段拨款、随时可停；
- 可验证性：原始数据、现场访问、第三方复核；
- 个人投入：自己的时间、现有设备和现场协调，不把风险全转给对方。

少任何一项，都容易变成“讲得很好，但我不敢给钱”。

## 10. 不要做的五件事

1. 不要一开口就要 5 万，也不要把“投资”与“验证预算”混在一起；
2. 不要在阶段 0 现场确认前买相机和边缘盒；
3. 不要承诺零漏检、零漏单、保证回本或保证拿到客户；
4. 不要用“AI 市场很大”替代一个真实工位的证据；
5. 不要在对外材料里写对方姓名或做明显定制，避免让人觉得被下套。

## 11. 如果对方还是不投

不要争辩，先拿到三个东西：

1. 一个具体反对意见：是技术、钱、客户关系，还是不相信团队？
2. 一个可验证的下一步：能否去看一个工位、介绍一个质量负责人、或指定一个人看演示？
3. 一个明确的拒绝理由：如果他现在不投，什么证据出现后愿意再看？

对方不投，也是一种验证结果。把它记录下来，比反复解释更有价值。
