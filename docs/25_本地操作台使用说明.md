# 本地操作台使用说明

> 日期：2026-11-21 ｜ 状态：单工位 MVP，已通过真实 UA Server、Edge Core、Node-RED 和 UA 写回在线演练
>
> 定位：让班组长或现场工程师不打开 Node-RED，也能完成开检、完工、查看队列/回执和处置死信。

## 1. 解决什么问题

Node-RED 适合事件编排、排障和实验室演示，不适合作为最终操作员界面。

本地操作台补齐：

- 当前工位状态；
- 当前工单和 SN；
- 开始检测；
- 完成工单；
- 检测计数和 NG 率；
- MES 回执镜像；
- Edge Core 队列和死信；
- 最近投递记录；
- 单条质量证据包查看、图片预览、JSON/HTML 下载；
- 按工单、SN、MES 回执号或 correlationId 检索证据；
- 死信重放和人工确认；
- 一键导出当前状态快照。

目标是降低现场对研发人员的依赖。

## 2. 安全默认值

- 默认只监听 `127.0.0.1:8780`；
- 使用 HTTP Basic 鉴权；
- 所有 POST 请求必须带 `X-Operator-Request: 1`，降低 CSRF 风险；
- UA 管理员账号、Edge API Token 只保存在服务端环境变量；
- 浏览器不接触 UA 密码和 Edge API Token；
- 页面不加载外部 CDN 或第三方脚本；
- JSON 响应和页面禁止缓存；
- 设置 `X-Frame-Options: DENY`、`nosniff` 和 `no-referrer`。

MVP 仍未包含 HTTPS 和角色权限。生产环境应放在反向代理后，并按角色拆分操作权限。

## 3. 配置

```bash
export UA_ENDPOINT='opc.tcp://127.0.0.1:4840'
export UA_ADMIN_USER='replace-with-admin-user'
export UA_ADMIN_PASS='replace-with-admin-password'
export UA_CLIENT_CERT="$PWD/certs/client/client_cert.der"
export UA_CLIENT_KEY="$PWD/certs/client/client_key.pem"
export UA_SERVER_CERT="$PWD/certs/server/server_cert.der"
export UA_CLIENT_APPLICATION_URI='urn:freeopcua:python:client'

export EDGE_API_BASE_URL='http://127.0.0.1:8770'
export EDGE_API_TOKEN='replace-with-edge-api-token'

export OPERATOR_CONSOLE_HOST='127.0.0.1'
export OPERATOR_CONSOLE_PORT='8780'
export OPERATOR_CONSOLE_USER='operator'
export OPERATOR_CONSOLE_PASSWORD='replace-with-strong-password'
```

可选：

- `UA_OPERATOR_TIMEOUT_SECONDS`：UA 连接和 Method 超时，默认 5 秒；
- `OPERATOR_EDGE_TIMEOUT_SECONDS`：Edge API 超时，默认 5 秒。

## 4. 启动

```bash
.venv/bin/python -m operator_console.main
```

浏览器访问：

```text
http://127.0.0.1:8780
```

浏览器会弹出 HTTP Basic 登录框，输入 `OPERATOR_CONSOLE_USER` 和 `OPERATOR_CONSOLE_PASSWORD`。

## 5. 页面功能

### 5.1 工位状态

读取真实 OPC UA 信息模型：

- `DeviceStatus`
- `CurrentWorkOrderId`
- `CurrentPartSN`
- `InspectCount/OkCount/NgCount`
- `NgRate`
- `LastResult/LastDefectType/LastConfidence/LastImageId/LastTimestamp`
- MES 回执变量

### 5.2 工单控制

开始检测：

- 输入工单号和目标数量；
- 调用真实 `StartInspection` Method；
- 返回拒绝原因时直接显示。

完成工单：

- 使用当前输入或当前工单号；
- 二次确认；
- 调用真实 `CompleteWorkOrder` Method。

### 5.3 Edge Core 状态

通过 Edge API 读取：

- 队列总数；
- PENDING/SENDING/RETRY_WAIT；
- 死信总数；
- 最近投递；
- MES 回执和 UA 写回确认状态。

### 5.4 死信处置

每个死信可以：

- 填写操作人和原因后重放；
- 填写操作人和处置结论后确认。

所有动作通过 Edge Core 既有 API 执行，操作人和原因进入审计记录。

### 5.5 状态快照

点击“导出快照”下载 JSON，内容包括：

- 工位状态；
- Edge Core 状态；
- 最近 200 条投递；
- 最近 200 条死信；
- 生成时间。

可用于现场排障、交接和客户验收证据。

## 6. HTTP 接口

| 方法 | 路径 | 功能 |
|---|---|---|
| GET | `/healthz` | 进程健康，不需要鉴权 |
| GET | `/` | 操作台页面 |
| GET | `/api/status` | UA 工位 + Edge Core 状态 |
| GET | `/api/deliveries?limit=30` | 最近投递 |
| GET | `/api/dead-letters?limit=30` | 最近死信 |
| GET | `/api/evidence/{deliveryId}` | 单条质量证据包 |
| GET | `/api/evidence/{deliveryId}/image` | 证据图片预览 |
| GET | `/api/evidence/search?q=...` | 证据检索 |
| GET | `/api/report` | 下载完整 JSON 快照 |
| POST | `/api/work-orders/start` | 开始检测 |
| POST | `/api/work-orders/complete` | 完成工单 |
| POST | `/api/dead-letters/{id}/replay` | 重放死信 |
| POST | `/api/dead-letters/{id}/acknowledge` | 确认处置死信 |

所有 `/api/*` 和静态页面需要 HTTP Basic；POST 还必须带：

```text
X-Operator-Request: 1
```

## 7. systemd 部署

部署模板新增：

```text
deploy/systemd/ua-linqinspect-operator.service.in
```

环境变量模板新增：

```text
OPERATOR_CONSOLE_HOST=127.0.0.1
OPERATOR_CONSOLE_PORT=8780
OPERATOR_CONSOLE_USER=operator
OPERATOR_CONSOLE_PASSWORD=CHANGE_ME
OPERATOR_EDGE_TIMEOUT_SECONDS=5
UA_OPERATOR_TIMEOUT_SECONDS=5
```

启用：

```bash
sudo systemctl enable --now ua-linqinspect-operator.service
```

服务本身只绑定回环地址。需要局域网访问时，应通过带 TLS 和访问控制的反向代理暴露。

## 9. 当前边界

MVP 尚未包含：

- 多工位切换；
- 用户角色分离；
- HTTPS；
- 企业统一身份认证；
- 图片预览和质量证据包；
- 返修/复检流程；
- 移动端专用布局和离线缓存。

这些能力应按真实客户使用反馈排序，不预先堆满页面。

## 10. 下一步

操作台首版稳定后，最自然的扩展是：

1. 质量证据包：关联图片、模型版本、MES 回执和 correlationId；
2. 返修/复检闭环；
3. 多工位切换；
4. 角色权限和 HTTPS 反向代理。

当前优先级不是继续加页面，而是让真实操作员用这个界面完成一轮开检、NG、完工和死信处置，记录卡点和人天。
