# OPC UA 回执写回适配器

> 日期：2026-11-21 ｜ 状态：独立进程可用，已通过真实安全 OPC UA 集成测试
>
> 目标：让 Edge Core 在收到合法 MES 回执后，通过受控 Method 写回 OPC UA，并在确认成功后才把投递推进到 `DONE`。

## 1. 它解决什么问题

Edge Core Worker 只负责 MES HTTP 调用和回执校验。MES 成功后的任务停在：

```text
UA_WRITE_PENDING
```

如果没有 UA 写回器，任务会永久停在这里。适配器负责补上最后一步：

```text
Edge Core API 查询 UA_WRITE_PENDING
  -> 读取 mesReceipt
  -> 调用外部 OPC UA RecordMesReceipt
  -> 校验 accepted=true
  -> POST /ua-write-result
  -> Edge Core 进入 DONE
```

## 2. 关键安全边界

- 只调用 `RecordMesReceipt`，不直接写 UA 变量；
- 必须使用签名加密连接和具备 Method 权限的账号；
- 回执类型只接受 `MES_ORDER` 和 `COMPLETION_RECEIPT`；
- 必须带 `receiptNo`、`workOrderId`、`correlationId`；
- UA Method 拒绝或连接失败不会报告成功；
- 失败会保留在 `UA_WRITE_PENDING` 并记录错误，后续轮询重试；
- 不修改当前工单和计数状态。

## 3. 配置

```bash
export EDGE_API_BASE_URL='http://127.0.0.1:8770'
export EDGE_API_TOKEN='replace-with-edge-api-token'
export UA_ENDPOINT='opc.tcp://127.0.0.1:4840'
export UA_CLIENT_CERT="$PWD/certs/client/client_cert.der"
export UA_CLIENT_KEY="$PWD/certs/client/client_key.pem"
export UA_SERVER_CERT="$PWD/certs/server/server_cert.der"
export UA_ADMIN_USER='replace-with-admin-user'
export UA_ADMIN_PASS='replace-with-admin-password'
```

可选：

- `QC_NAMESPACE_URI`：默认 `urn:fde:linqinspect:qc`
- `QC_STATION_NODE_NAME`：默认 `QCStation`
- `QC_RECEIPT_METHOD_NAME`：默认 `RecordMesReceipt`
- `UA_CLIENT_APPLICATION_URI`：必须与客户端证书 URI 一致
- `UA_WRITEBACK_TIMEOUT_SECONDS`：默认 5
- `UA_WRITEBACK_BATCH_LIMIT`：默认 50

## 4. 运行

单批执行，适合 cron、systemd timer 或人工检查：

```bash
.venv/bin/python scripts/run_ua_writeback_adapter.py --once
```

常驻轮询：

```bash
.venv/bin/python scripts/run_ua_writeback_adapter.py --interval 2
```

## 5. 验证

`tests/ua_writeback_adapter_test.py` 覆盖：

1. 批量处理中成功与失败分别回报；
2. 缺失回执不会报告成功；
3. 真实安全 OPC UA 连接调用 `RecordMesReceipt`，成功后 Edge Core 进入 `DONE`。

当前结果：**3/3 PASS**。

## 6. 当前边界

- 适配器是独立进程，尚未纳入 systemd 模板；
- 失败只记录到 `UA_WRITE_PENDING`，尚未设置 UA 写回专用重试上限和死信策略；
- 尚未完成多 Edge Core 实例或 HA 协调；
- 真实工厂 UA Server 的证书和 Method 权限仍需现场联调；
- 适配器存在不代表发送泵已经切换；新事件直写 Edge Core 和双泵互锁仍是后续工作。
