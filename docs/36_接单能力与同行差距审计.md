# 接单能力与同行差距审计

日期：2026-11-22  
审计对象：`UA_LinqInspect` 当前主线代码与交付材料  
审计口径：能否由非开发者独立完成一个真实工位的安装、调试、验收和售后，而不是能否演示。

## 1. 结论先行

**当前可以演示，也可以做付费的质检/MES 技术诊断；不能按“交钥匙 AI 质检系统”接单。**

项目真正的强项不是“视觉模型很准”，而是：

- 质检结果进入 MES 的可靠投递：SQLite Outbox、重试、死信、人工重放、回执确认。
- 质检证据链：工单、SN、图片、模型版本、MES 回执、correlationId 可追溯。
- 失败可处置：断网、MES 超时、进程重启、写回前崩溃都有自动化验证。
- 单工位操作台和运维基线：开检/完工、队列、死信、备份、健康探针、systemd 模板。

当前最硬的缺口是：

1. 没有真实相机、镜头、光源、工装和触发/标定链路。
2. 没有客户真实样本，视觉指标只对合成数据成立。
3. 没有真实 MES 沙箱，现有 MES 是本地模拟 HTTP 端。
4. 没有现场调试向导、安装包、升级/回滚和售后边界。
5. 没有多工位、多产品族和规模化交付经验。

因此，现阶段更适合把自己定位为 **“质检结果到 MES 的可靠交付与证据层”**，而不是和 Cognex、Keyence、HALCON 正面竞争“通用视觉平台”。

## 2. 现在能接什么，不能接什么

| 业务 | 现在能否做 | 边界 |
|---|---|---|
| 5～30 分钟软件演示 | 可以 | 必须明确 MES、PLC、相机为模拟或缺失 |
| 质检-MES 对账诊断 | 可以，建议作为第一笔收费 | 客户提供接口文档、样例数据和测试环境 |
| 单站 PoC / 技术验证 | 有条件可以 | 客户提供相机、样件、MES 沙箱和现场配合；仍需开发者驻场 |
| 交钥匙视觉质检工位 | 不可以 | 缺少光学、工装、现场调试和真实精度验证 |
| 按生产节拍无人值守运行 | 不可以 | 没有现场长稳、异常处置和 SLA 证据 |
| 多工位/整线复制 | 不可以 | 当前只有单工位模型，没有多站编排和集中运维 |
| 承诺零漏检、零漏单、exactly-once | 不可以 | 技术上也不应这样承诺 |

**接单判断：当前应接“诊断/联合验证”，不应接“生产交付”。**

## 3. 工程事实核查

### 3.1 已经真实存在的部分

- `edge_core/`：SQLite 状态机、Outbox、重试、死信、重放、MES 回执校验、证据包。
- `operator_console/`：开检、完工、投递查看、死信处置、证据检索与导出。
- `deploy/`：systemd、健康探针、Prometheus 告警、备份 timer、恢复脚本模板。
- `tests/`：覆盖崩溃恢复、断网、MES 错误分类、幂等冲突、备份恢复和证据治理。
- `scripts/vision_demo.py`：真实本地推理、图像质量门禁、置信度门禁、模型卡；但训练/验证图像是程序合成。

### 3.2 仍是模拟或占位的部分

- `server/qc_server.py:1209` 起的虚拟检测循环仍用随机数生成 OK/NG、缺陷和置信度；`1216-1221` 明确保留 `TODO(YOLOv8 切换点)`。
- `scripts/vision_demo.py:50-57` 明确写明：合成图像、闭集分类、概率未做现场校准、没有真实相机/光源/工装。
- `edge_core/config.py:53` 只配置一个通用 `MES_BASE_URL`；没有 SAP、Siemens、Rockwell 等厂商适配器，也没有真实 MES 沙箱合同。
- `operator_console/server.py` 的操作面是工单、投递、证据和死信；没有相机取图、曝光/触发、ROI、标定、模型发布等视觉工位配置。
- `deploy/README.md` 是手工部署步骤，不是可交付安装包；没有配置向导、版本升级、回滚包和现场自检命令。
- 现有“视觉入口”和“质检-MES 链路”还没有合成一个可由现场人员独立操作的完整工位产品。

### 3.3 测试证据

项目已有较完整的自动化回归。本轮完整隔离回归于 2026-11-22 通过：44 个测试脚本、0 失败，证据为 `.tmp/regression-20261122-130707/summary.json`；历史文档汇总为 689 项断言/用例。测试通过只证明软件行为，不证明真实产线精度或客户验收。`.tmp` 不入库，正式交付时应另存为发布证据包。

## 4. 与同行的差距

| 对比对象 | 同行强在哪里 | 你现在缺什么 | 你能赢在哪里 |
|---|---|---|---|
| Cognex、Keyence、MVTec HALCON、Landing AI 类视觉平台 | 相机/光学选型、成像工装、标定、模型工具、现场服务、成熟案例 | 真实成像链路、样本管理、模型评估、误检回流、现场调参 | 轻量、可定制的质检-MES 交付层；不绑定某一家视觉平台 |
| Siemens Opcenter、Rockwell FactoryTalk、SAP DM/ME 类 MES 质量模块 | ISA-95、工单/批次谱系、SPC、返修/处置、审计、企业级集成 | 真实 MES 适配器、业务主数据、质量流程深度、企业级权限 | 边缘侧快速接入、断网补传、逐笔对账、证据包 |
| Kepware、Ignition、HighByte 类工业数据平台 | 多协议接入、Tag 管理、历史库、UNS、诊断、冗余 | 多协议驱动、 historian、远程运维、设备模板库 | 聚焦“质检结果如何变成 MES 业务动作”，而不是做通用网关 |
| 视觉系统集成商/自动化集成商 | 现场勘测、光学工装、PLC 联动、安装施工、备件和 SLA | 现场施工能力、硬件供应链、服务网络、验收经验 | 软件可靠性、可追溯性、标准化交付和较低复制成本 |
| Tulip、AWS Greengrass、Azure IoT Edge 类平台 | 低代码应用、设备身份、OTA、边缘模块生命周期、集中管理 | 配置化、远程升级、设备群管理、多租户 | 单站闭环更深、MES 事务语义更明确、部署更轻 |

**判断：不要在“通用视觉精度”和“完整 MES 功能”上正面竞争。你的差异化应是“质检结果不丢、不重、可对账、可追溯地进入 MES”，并且能适配不同视觉前端。**

## 5. 接单前必须补齐的八个门槛

| 门槛 | 最低可交付标准 | 当前状态 |
|---|---|---|
| 真实相机与光学 | 至少一种工业相机 SDK/GenICam 接入；镜头、光源、支架、触发方式确定；能稳定取图 | 未完成 |
| 现场标定 | ROI、焦距/工作距离、曝光、白平衡、图像质量门禁可按工位配置 | 只有图像质量门禁，无标定流程 |
| 真实样本与评估 | 300+ 件真实样件，3～5 类缺陷，独立留出集，类别级 Recall/Precision、误检成本 | 只有合成数据 |
| 真实 MES 沙箱 | 鉴权、幂等键、错误码、回执、重复请求、冲突处理、逐笔对账 | 只有本地模拟 MES |
| 工位调试 | 配置向导/检查单：相机、工单、SN、MES、阈值、试跑、签字 | 有文档模板，无产品化向导 |
| 安装与升级 | 一键安装、依赖锁定、配置备份、版本升级、失败回滚 | 手工部署模板 |
| 运维与售后 | 日志、指标、告警、备份恢复、远程支持边界、响应时限 | 有技术基线，无 SLA 和服务流程 |
| 安全与数据 | 企业 PKI/账号分级、网络隔离、数据归属、保留/删除、审计 | 本地 CA 和单管理员，实验级 |

## 6. 最小可售单站包

在第一单之前，只做一个产品族、一个工位、3～5 类缺陷，不要扩整线。

### Gate A：真实视觉台架

- 真实工业相机 + 镜头 + 光源 + 固定工装。
- 300+ 件真实 OK/NG 样件，标注规则和验收人提前确认。
- 输出类别级 Recall/Precision、混淆矩阵、误检/漏检样例、单件处理耗时。
- 未知缺陷、低置信度和图像质量不合格必须转人工，不自动放行或开单。

### Gate B：真实 MES 沙箱

- 完成一次真实鉴权、开单、报工、回执和重复请求测试。
- 逐笔对账：业务键、MES 回执号、UA 回执、证据包能对应。
- 72 小时影子运行或 3 个班次，记录重复、丢失、死信和恢复时间。
- 不以“HTTP 200”代替“MES 已受理”，不以模拟 MES 代替沙箱。

### Gate C：可交付软件包

- 安装脚本、配置样例、现场检查单、备份/恢复、升级/回滚、故障手册。
- 操作台能完成开检、完工、异常复核、死信重放和证据导出。
- 一次由非开发者按文档独立完成的安装演练。
- 一份双方签字的验收报告和明确的支持边界。

**三关全过，才谈“接单”；只过一关，只能叫“验证项目”。**

## 7. 建议的未来 60 天

| 周期 | 目标 | 产出 |
|---|---|---|
| 第 1～2 周 | 找一台可借/可租的工业相机，搭最小光学台架 | 真实图像采集记录、镜头/光源/工装清单 |
| 第 3～4 周 | 接相机适配器，建立样本清单和评估脚本 | 真实样本集、类别级指标、失败样例 |
| 第 5～6 周 | 找一家愿意提供 MES 沙箱的工厂做联调 | 真实 MES 回执、72h 影子对账、问题清单 |
| 第 7～8 周 | 把安装、配置、备份、回滚和验收文档跑一遍 | 单站可交付包、一次非开发者安装演练 |

如果 60 天内拿不到真实样件或 MES 沙箱，不应继续加功能，应先解决现场准入。

## 8. 对外不要说的话

- “我们已经可以接生产单。”
- “AI 准确率很高”，但拿不出真实标注集和类别级指标。
- “已经对接 MES”，但只是本地模拟 HTTP 服务。
- “零漏检、零漏单、exactly-once。”
- “收到 MES 回执”等于“MES 已入库”。
- “合成数据准确率”等于“现场精度”。

## 9. 最终判断

这个项目已经越过“纯 Demo”阶段，工程可靠性是它的真优势；但还没有越过“可交付产品”阶段。  
下一步不是继续堆页面或功能，而是用真实相机、真实样件和真实 MES 沙箱，跑通一个可验收的单站闭环。
