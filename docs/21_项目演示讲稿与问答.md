# 项目演示讲稿与问答

> 用途：现场讲解、技术复核和试点沟通。讲稿的原则是“先讲问题，再跑证据，最后说边界”，不把模拟能力包装成生产事实。

## 1. 三分钟版本

### 0:00–0:40｜问题

> 工厂里真正难的不是再买一台相机。难的是相机或质检员已经发现不良品，但这条结果不能可靠进入 MES。MES 一超时、网络一断、设备一重启，就可能漏单、重复开单，月底还要人工对账。设备停机以后，质量损失又说不清发生在哪个时间窗。

### 0:40–1:30｜现场运行

打开 `http://127.0.0.1:8899/overview`，点击“现场运行演示”。

> 现在跑的不是视频，而是两套项目代码。左边设备上下文项目启动 Mock PLC，注入停机和温度异常；右侧质量交付主线收到 NG 后进入 SQLite Outbox，经历故障、重试、死信、重启和人工重放，最后拿到 MES 回执。

### 1:30–2:35｜结果

按以下顺序讲：

1. `DONE`：只有 MES 回执和 OPC UA 写回都确认，交付才结束；
2. MES 回执：同一个业务键不会重复形成业务结果；
3. OEE：A/P/Q 每个数字都能下钻到来源；
4. RCA：温度异常只是候选原因，有时间窗证据，但不冒充因果结论；
5. 审计：失败、死信和重放轨迹都保留，不是一条“成功日志”。

### 2:35–3:00｜边界

> 今天还没有接客户真实 PLC、真实 MES 和真实产线网络，所以这不能包装成生产验收。当前定位是可运行的软件先行 PoC+。下一步要用单工位付费试点验证 MES 沙箱、故障恢复、实施人天和复制能力。

## 2. 十分钟版本

1. **业务问题**：质检结果与 MES 断裂，导致漏单、重复开单、对账成本和设备损失无法解释。
2. **三部分关系**：Node-RED 保留现场编排；Edge Core 承接可靠交付；设备上下文项目补充 OEE/RCA。
3. **现场运行**：打开 `/overview`，点击运行，不预录、不跳步。
4. **结果证据**：`DONE`、MES 回执、OEE、RCA 候选和审计轨迹逐项解释。
5. **联合细节**：打开 `/joint`，说明设备异常、质量事件和交付状态如何按业务键与时间窗对齐。
6. **真/模拟边界**：主动说明 Mock PLC、模拟 MES、未接入生产网络和未承诺 exactly-once。
7. **能力分层**：质量连接器、设备上下文包、OEE/RCA 增值层可以分阶段落地。
8. **目标客户**：已有 MES/质检但闭环不可靠的工厂；MES 厂商、系统集成商和视觉厂商可作为渠道。
9. **90 天计划**：单工位试点、MES 沙箱验收、标准交付包、第二现场复制。
10. **下一步问题**：问题是否真实、证据是否可复现、路径是否可标准化。

## 3. 现场演示顺序

1. 打开 `http://127.0.0.1:8899/overview`；
2. 先用 30 秒讲问题，不解释技术名词；
3. 点击“现场运行演示”；
4. 运行期间只说明“这是两套真实项目代码在协作，不是视频”；
5. 结果出来后按 `DONE → 回执 → OEE → RCA → 审计` 顺序讲；
6. 打开 `/joint` 只补充故障恢复和审计细节，不逐行讲代码；
7. 最后回到总览页，讲三层能力和 90 天计划；
8. 用“当前需要回答的三个问题”收尾，不要求现场做决定。

## 4. 常见问题

### 这不就是又一个视觉项目吗？

不是。视觉可以换供应商，人工质检也可以接入。我们标准化的是质检结果之后的可靠交付、回执对账和设备上下文。视觉是可选增值层，不是项目主线。

### OPC UA 和 YOLO 都不是新技术，壁垒在哪里？

单点技术不是壁垒。壁垒是现场故障样本、MES 适配器、事务状态机、回执审计、部署验收工具和渠道复用。客户买的是“出故障也不丢单、能对账”，不是协议栈本身。

### MES 厂商自己不会做吗？

会做一部分，但他们的项目通常绑定自家 MES，跨品牌、跨老旧设备和多类质检源仍需要重复定制。我们可以做 MES 厂商的模块和渠道，而不是正面替代 MES。

### 没有硬件，凭什么证明？

硬件未到之前，最值钱的是软件可靠性，不是相机参数。我们已经把事务、幂等、重试、死信、重启恢复、回执和设备上下文跑通；硬件到位后更换接入层，不推翻已验证的软件底座。

### 之前不是有一套工作流吗？现在为什么还有第二个项目？

两套项目是互补关系，不是替代关系。Node-RED 工作流保留现场编排和快速接入；Edge Core 把发送泵、事务、下载恢复和审计收稳；设备上下文项目独立采集 PLC 状态、产量、温度和报警。联合后，质量结果不仅能交付，还能解释损失发生在哪里。

### 当前离生产还差什么？

至少还差真实 PLC 点位、客户 MES 沙箱、生产网络与安全评审、长期稳定性数据、实施人天测量、运维流程和付费试点验证。

### 最大风险是什么？

不是代码写不出来，而是无边界定制、免费 POC、交付人天失控和客户集中。控制方式是付费试点、范围边界、标准人天上限、变更单、适配器复用和跨客户验收。

### 多久能看到下一步验证结果？

以 90 天为一个验证周期：拿到一个单工位试点的 MES 沙箱验收、回执对账和故障恢复数据；再争取第二个独立现场或渠道伙伴。达不到就调整产品与销售假设，不用主观预期硬撑范围。

### RCA 是不是已经知道真正原因？

不是。RCA 当前输出的是同一时间窗内的候选原因和证据，工程人员仍需复核。系统不把时间相关写成因果证明。

## 5. 不要说的话

- 不说已经完成生产集成；
- 不说能保证 exactly-once；
- 不说任意 PLC/MES 零配置接入；
- 不把模拟 MES 说成客户 MES；
- 不把 RCA 时间重合说成因果证明；
- 不在没有试点数据时虚构客单价、毛利和回款周期；
- 不把针对某个人或某次会面的定制页面当成标准产品。

## 6. 现场失败时怎么说

如果联合演示无法运行，先不要跳过错误。可以直接说明：

> 这个场景依赖同级设备上下文仓库、Node 依赖和本地端口。现在失败的是演示环境，不代表交付链路通过。我先看终端错误并恢复环境，再重新运行；不会用预录结果代替现场证据。

然后按 [项目总览与现场演示](20_项目总览与现场演示.md#8-现场演示检查清单) 的检查清单排查。
