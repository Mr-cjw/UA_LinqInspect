# 陈总投资评审版：先卖可靠性，再卖设备解释

> 用途：投资沟通、现场演示和后续尽调。页面不是生产验收报告，所有模拟边界必须与真实能力一起展示。

## 1. 现场打开什么

```bash
cd ~/project_files/UA_LinqInspect
.venv/bin/python scripts/demo_edge_core.py --ui --no-open
```

浏览器打开 `http://127.0.0.1:8899/investor`，点击“现在跑给陈总看”。

页面约 15 秒完成一次联合场景：设备停机与温度异常 → 一条 NG → SQLite/Edge Core 投递 → MES 回执与 UA 写回 → OEE 分解 → RCA 候选原因。

## 2. 陈总先记住三句话

1. 工厂不缺相机，缺的是让质检结果可靠进入 MES 的最后一公里；
2. 我们不是再做一个视觉算法，而是做可审计、可恢复、可复制的工业软件连接器；
3. 先卖单站连接器，再扩设备上下文与 OEE/RCA，用付费试点换取跨客户复制证据。

## 3. 一条 NG 的价值链路

### 没有这套系统

- NG 靠人工登记，MES 超时或断网后容易漏单；
- 重复上报可能重复开单，月底只能靠 Excel 对账；
- 设备停机、温度异常与质量结果分散在不同系统，无法形成证据链；
- 每个客户重复开发接口，项目做完仍难复制。

### 有这套系统

- 业务事件先进入本地事务队列，MES 不在线也不会静默丢失；
- 同一业务键幂等，重试失败进入可见死信，人工重放保留原回执和审计；
- 只有 MES 回执与 UA 写回都确认，交付才进入 `DONE`；
- 同一时间窗下钻到 OEE 的 A/P/Q，并把设备异常列为有证据的 RCA 候选。

## 4. 今天演示真正证明了什么

| 结论 | 证据 | 投资含义 |
|---|---|---|
| 质检结果不会因 MES 故障静默消失 | SQLite Outbox、重试、死信与重放 | 可靠性有可验收的软件底座 |
| 重复上报不会重复形成业务结果 | 业务键幂等与回执校验 | 降低重复开单和对账成本 |
| 服务重启后还能继续 | 真实重建服务并恢复持久化任务 | 现场运维风险可被控制 |
| 业务结果和设备上下文能对齐 | 两个仓库联合运行，共享工单、SN 与时间窗 | 可扩成 OEE/RCA 增值收入 |
| 结果不是预录动画 | 每次运行都会生成新的 deliveryId、correlationId 和回执 | 投资人可现场复验 |

## 5. 明确没有证明什么

- 没有接客户真实 PLC 点位、真实节拍和真实产线网络；
- 没有接客户真实 MES，当前 MES 和 UA 回执写回是本地模拟；
- 没有证明付费意愿、实施人天、回款周期和跨客户复制；
- RCA 只表示时间关联，不构成因果证明；
- 系统承诺 at-least-once + 业务幂等，不承诺 exactly-once。

这些不是演示缺陷，而是下一轮融资要换回来的商业证据。

## 6. 为什么这是生意

| 层次 | 卖什么 | 客户为什么买 | 收入形式 |
|---|---|---|---|
| 质量连接器 | 质检结果到 MES 的可靠交付 | 漏单、重复开单、人工对账直接影响现金流 | 试点启动款、实施费、年度许可 |
| 设备上下文包 | PLC 状态、产量、温度、报警采集 | 质量损失需要设备证据，不能只看结果 | 按工位/产线订阅、维保升级 |
| OEE/RCA 增值包 | 损失分解与候选根因 | 从“发现问题”进入“解释和改善” | 分析订阅、行业模板、OEM 白标 |

扩张顺序固定：单工位 → 多工位 → 单产线 → 多工厂；单 MES → 适配器库；连接器 → 设备上下文 → 分析增值。

## 7. 90 天用钱换什么

1. 第 1–2 周：锁定一个产品族、一种工单、一套 MES 接口和一个 PLC 只读点位集；
2. 第 3–6 周：在客户 MES 沙箱完成幂等合同、故障恢复、回执对账和 RTO 验收；
3. 第 7–9 周：沉淀部署模板、适配器、验收脚本和故障演练手册；
4. 第 10–12 周：争取第二个独立客户或渠道伙伴，验证可复制性。

建议资金优先级：产品化与付费试点 45%，渠道与 MES 合作 25%，可靠性与现场支持 20%，视觉模块有界研发 10%。具体金额按 12 个月团队成本、试点预算和现金缺口倒推，不在演示材料中虚构估值。

## 8. 为什么先从江西做

- 江西有大量离散制造企业，质量、设备和 MES 的割裂问题具有共性；
- 本地 MES 厂商、系统集成商和自动化伙伴可以成为渠道，而不是全部靠直销；
- 地理半径短，适合先做单工位付费试点和快速现场复验；
- 先在一省形成标准交付包和参考案例，再向邻近制造业区域复制。

这里不假设“江西市场一定容易”，而是把它作为低成本验证渠道假设的第一站。

## 9. 陈总今天只需判断三件事

1. **问题够不够痛**：质量结果进不了 MES，是否会造成漏单、重复开单和人工对账；
2. **证据够不够硬**：现场可运行、可失败、可恢复、可审计的代码链，是否比概念 BP 更可信；
3. **路径够不够清楚**：先卖单站连接器、再扩设备上下文与分析，是否比一开始做大型 MES 更可控。

如果这三个判断成立，本轮投资应优先购买“付费试点和商业证据”，而不是继续扩大 Demo 范围。
