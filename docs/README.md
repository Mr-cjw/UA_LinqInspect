# 文档导航：从这里开始掌握项目

这套文档把“需求、架构、代码、运行、验收、排障”组织成一条学习路径。建议先读本页，再按顺序阅读其他文档；需要查细节时回到原始设计文档。

## 1. 先用一句话记住项目

**虚拟 AI 质检结果写入 asyncua OPC UA Server，Node-RED 通过自定义事件订阅质检结果，按规则生成 MES 工单/报工，并把 MES 回执写回 UA 变量，形成 OT-IT 质检闭环。**

核心链路只有这一条：

```text
虚拟质检数据源 -> OPC UA Server -> Node-RED 边缘流 -> 模拟 MES
                                      |                    |
                                      +---- 回执写回 UA <---+
```

## 4. 推荐学习路径

### 30 分钟：建立正确地图

1. 阅读 [00_项目全景与架构.md](00_项目全景与架构.md) 的架构图和两条时序图。

3. 记住三条主线：工单状态、事件通知、MES 缓冲队列。

### 2 小时：代码和链路对齐

1. 按 [02_代码与NodeRED导读.md](02_代码与NodeRED导读.md) 阅读 `server/qc_server.py`。

3. 按 [03_运行验证与排障手册.md](03_运行验证与排障手册.md) 启动并跑一遍 M1/M2 测试。

### 半天：完成一次真正的掌握验证

1. 手工演示正常 NG 流、超时重试、5xx 死信、Method 拒绝四个场景。
2. 解释每一步的日志、变量变化和队列状态。
3. 不看文档画出完整时序图。
4. 选择一个练习任务，例如新增缺陷码或实现 SQLite 持久化。
5. 准备答辩或工厂立项时，阅读 [06_作品集答辩与工厂试点落地.md](06_作品集答辩与工厂试点落地.md)。

## 6. 项目一句话与三句话

### 一句话

用 OPC UA 事件把虚拟质检结果送到 Node-RED，由边缘队列可靠地完成 MES 开单/报工并写回回执。

### 三句话

1. Server 负责表达质检信息模型，并用 Method 管工单、用 Event 报结果。
2. Node-RED 负责事件解析、去重、削峰、缓冲、重试和死信，不直接改业务状态。
3. MES 是模拟 HTTP 服务，NG 回执写 `LastNgMesOrderNo`，完工回执写 `LastCompletionReceiptNo`，`LastMesOrderNo` 仅作兼容镜像，不覆盖派工单号。
