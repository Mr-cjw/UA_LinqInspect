# 信息模型与业务规则速查

本文是 `Phase0_需求拆解与信息模型.md`、`M1_业务口径与MES契约.md` 和实际代码的对齐速查。写代码、联调、答辩前优先看这里。

## 1. 命名空间与 NodeId 规范

| 项 | 值 |
|---|---|
| NamespaceUri | `urn:fde:linqinspect:qc` |
| 常规 NamespaceIndex | `ns=2` |
| NodeId 风格 | `ns=2;s=<可读名>` |
| BrowseName 风格 | `2:<可读名>` |
| 安全策略 | 本地 CA + `Basic256Sha256_SignAndEncrypt`；匿名只读；管理员可调用 Method；控制、追溯和 MES 回执变量均外部只读 |

示例：

```text
ns=2;s=QCStation
ns=2;s=QCStation.DeviceStatus
ns=2;s=QCStation.StartInspection
ns=2;s=NgDetectedEventType
```

## 2. 地址空间对象树

```text
Objects
└── QCStation
    ├── DeviceStatus              Int32 RO（Method 驱动）
    ├── CurrentWorkOrderId        String RO（Method 驱动）
    ├── CurrentPartSN             String RO（检测入口驱动）
    ├── LastMesOrderNo            String RO（兼容镜像，RecordMesReceipt 更新）
    ├── LastNgMesOrderNo          String RO
    ├── LastCompletionReceiptNo   String RO
    ├── StartInspection           Method
    ├── CompleteWorkOrder         Method
    ├── RecordMesReceipt          Method
    ├── AcknowledgeEvent          Method
    ├── ExportPendingEvents       Method
    ├── PurgeOutbox               Method
    ├── ResetCounters             Method
    ├── Inspection
    │   ├── LastResult            Boolean RO
    │   ├── LastDefectType        String RO
    │   ├── LastConfidence        Double RO
    │   ├── LastImageId           String RO
    │   ├── LastTimestamp         DateTime RO
    │   └── NgRate                Double RO
    ├── Statistics
    │   ├── InspectCount          UInt32 RO
    │   ├── OkCount               UInt32 RO
    │   └── NgCount               UInt32 RO
    └── Events                    Event Notifier
        ├── OutboxStatus          String RO（JSON 摘要）
        ├── PendingEventCount     UInt32 RO
        ├── OldestPendingEventAge Double RO
        ├── OldestPendingEventAt  String RO
        ├── OutboxCapacity        UInt32 RO
        ├── OutboxHighWatermark   UInt32 RO
        └── OutboxBackpressure    Boolean RO
```

共 22 个变量：3 个根层只读控制变量、3 个根层只读 MES 回执变量、6 个 Inspection 只读变量、3 个 Statistics 只读变量、7 个 Events 只读积压状态变量。

## 3. 变量语义

| 变量 | 类型 | 权限 | 谁写 | 含义 |
|---|---|---|---|---|
| `DeviceStatus` | Int32 | RO | `StartInspection`/`CompleteWorkOrder` | `0=Idle`、`1=Running`、`2=Fault` |
| `CurrentWorkOrderId` | String | RO | `StartInspection`/`CompleteWorkOrder` | 当前派工工单 |
| `CurrentPartSN` | String | RO | Server 检测入口 | 当前单件序列号 |
| `LastMesOrderNo` | String | RO | `RecordMesReceipt` | 最近一次 MES 回执的兼容镜像 |
| `LastNgMesOrderNo` | String | RO | `RecordMesReceipt` | 最近一次 NG 开单回执 `MES-*` |
| `LastCompletionReceiptNo` | String | RO | `RecordMesReceipt` | 最近一次完工报工回执 `RC-*` |
| `LastResult` | Boolean | RO | Server | `True=OK`、`False=NG` |
| `LastDefectType` | String | RO | Server | OK 时为空串；NG 时为缺陷码 |
| `LastConfidence` | Double | RO | Server | 0.0~1.0 |
| `LastImageId` | String | RO | Server | 图像/样本号 |
| `LastTimestamp` | DateTime | RO | Server | UTC 检测时间 |
| `NgRate` | Double | RO | Server | 滑动窗口 NG 率，空窗口 `-1.0` |
| `InspectCount` | UInt32 | RO | Server | 累计检测数 |
| `OkCount` | UInt32 | RO | Server | 累计 OK 数 |
| `NgCount` | UInt32 | RO | Server | 累计 NG 数 |
| `OutboxStatus` | String | RO | Server | outbox JSON 摘要，供 Node-RED 心跳读取 |
| `PendingEventCount` | UInt32 | RO | Server | 待 ACK 的 NG/完工事件数 |
| `OldestPendingEventAge` | Double | RO | Server | 最老待确认事件年龄（秒） |
| `OldestPendingEventAt` | String | RO | Server | 最老待确认事件创建时间 |
| `OutboxCapacity` | UInt32 | RO | Server | `QC_OUTBOX_MAX_PENDING` 硬上限 |
| `OutboxHighWatermark` | UInt32 | RO | Server | 触发背压和拒绝新开检的阈值 |
| `OutboxBackpressure` | Boolean | RO | Server | 是否已达到高水位 |

## 4. Method 契约

### 4.1 StartInspection

```text
输入: workOrderId:String, targetCount:UInt32
输出: accepted:Boolean, summary:String
```

| 前置条件 | 行为 |
|---|---|
| `workOrderId` 为空 | 拒绝：`empty workOrderId` |
| 正在 Running，且传入同一个工单 | 幂等接受：`already running` |
| 正在 Running，但传入不同工单 | 拒绝：`already running with different work order ...` |
| `DeviceStatus=Fault` | 拒绝：`DeviceStatus=Fault` |
| `targetCount<=0` | 拒绝：`targetCount must be > 0` |
| outbox 积压达到高水位 | 拒绝：`event outbox backpressure`，提示先 ACK 或受控清空 |
| 合法且 Idle | 绑定工单，置 Running |

### 4.2 CompleteWorkOrder

```text
输入: workOrderId:String
输出: accepted:Boolean, summary:String
```

| 前置条件 | 行为 |
|---|---|
| 无活动工单 | 拒绝：`no active work order` |
| 传入工单与当前工单不一致 | 拒绝：`workOrderId mismatch, expected ...` |
| `DeviceStatus!=Running` | 拒绝：`DeviceStatus=... is not Running` |
| 全部通过 | 发 `WorkOrderCompletedEvent`；回 Idle；清空当前工单 |

成功后的 `summary` 包含：

```text
workOrder=<id> inspect=<n> ok=<n> ng=<n> ngRate=<x.xxx>
```

### 4.3 AcknowledgeEvent

```text
输入: eventId:String（也可传稳定 CorrelationId）
输出: accepted:Boolean, summary:String
```

Node-RED 把事件成功写入 SQLite 队列后调用。仅删除对应待确认 outbox 事件；未知或已 ACK 的 ID 返回成功，保持幂等。空字符串拒绝。

### 4.4 ExportPendingEvents

```text
输入: offset:UInt32, limit:UInt32
输出: accepted:Boolean, payload:String(JSON)
```

管理员分页读取待确认 outbox。返回 `pendingCount`、`events`、`hasMore` 和绑定当前事件 ID 列表的 `purgeToken`。单页上限由 `QC_OUTBOX_EXPORT_LIMIT` 控制，默认 500。匿名会话不能调用。

### 4.5 PurgeOutbox

```text
输入: confirmToken:String
输出: accepted:Boolean, summary:String
```

仅当令牌等于当前 outbox 快照令牌时删除全部待确认事件；错误或过期令牌拒绝，outbox 已空时幂等接受。该操作会写审计日志，只应用于人工导出留证后的受控处置。匿名会话不能调用。

### 4.6 ResetCounters

清零累计统计和滑动窗口，并将 `NgRate` 恢复为 `-1.0`。

### 4.7 RecordMesReceipt

```text
输入: receiptType:String, receiptNo:String, workOrderId:String, correlationId:String
输出: accepted:Boolean, summary:String
```

`receiptType` 只接受 `ng` 或 `complete`。Method 校验非空回执号、工单号、关联 ID 和长度后，在同一把状态锁内写具体回执变量与 `LastMesOrderNo` 兼容镜像，并读回确认。`ng` 更新 `LastNgMesOrderNo`，`complete` 更新 `LastCompletionReceiptNo`；两者都不得覆盖 `CurrentWorkOrderId`。客户端直接写三个回执变量会被拒绝。

## 5. 事件模型

三个自定义 EventType 都继承 `BaseEventType`，通过 `QCStation.Events` 触发。

| EventType | 触发条件 | 自定义字段 |
|---|---|---|
| `InspectionFinishedEventType` | 每次检测完成（尽力发布） | WorkOrderId, SerialNumber, Result, DefectType, Confidence, ImageId, CorrelationId, SourceEventId, EventVersion |
| `NgDetectedEventType` | 每次检测为 NG（持久化 outbox） | WorkOrderId, SerialNumber, DefectType, Confidence, ImageId, CorrelationId, SourceEventId, EventVersion |
| `WorkOrderCompletedEventType` | `CompleteWorkOrder` 成功（持久化 outbox） | WorkOrderId, InspectCount, OkCount, NgCount, NgRate, CorrelationId, SourceEventId, EventVersion |

注意事项：

- 客户端必须显式订阅具体 EventType；只订阅 `BaseEventType` 可能收不到自定义字段。
- `NgDetectedEventType` 是 Node-RED NG 开单的唯一事件来源。
- `WorkOrderCompletedEventType` 是 MES 报工的唯一事件来源。
- 同一次 NG 检测的 `InspectionFinishedEvent` 与 `NgDetectedEvent` 共用 `CorrelationId`；Node-RED 透传到 MES 请求头与请求体。
- `SourceEventId` 在重发间保持不变；消费端必须按它或业务指纹幂等，不能把 at-least-once 当 exactly-once。

## 6. 缺陷码

| 缺陷码 | 含义 | 默认严重度 |
|---|---|---|
| `SCRATCH` | 划痕 | 3 |
| `DENT` | 凹陷 | 3 |
| `STAIN` | 污渍 | 2 |
| `BURR` | 毛刺 | 3 |
| `MISSING` | 缺件 | 4 |

规则：全大写英文；OK 的 `LastDefectType` 必须为空串；新增缺陷码时同步修改 `server/qc_server.py` 的 `DEFECT_CODES` 与 M1 文档。

## 7. NgRate 滑动窗口

| 项 | 规则 |
|---|---|
| 窗口类型 | 按样本数的 FIFO 队列 |
| 默认大小 | 20 |
| 可配置 | `QC_NG_WINDOW` |
| 计算 | 窗口内 NG 数 / 窗口内样本数 |
| 空窗口 | `-1.0`，表示“无样本”，不是 0% |
| 报警阈值 | Node-RED 约定 `>=0.30` 且 `!=-1.0` |
| 累计统计 | `NgCount/InspectCount` 是整班次累计，不能与窗口率混用 |

独立 `NgRate` 变量和 `WorkOrderCompletedEventType.NgRate` 都遵守 `-1.0` 空窗口语义；MES 必须把 `-1.0` 解释为“样本不足”，不能当作 0% 不良率。

## 8. MES HTTP 契约

### 8.1 NG 开单

```http
POST /mes/ng-order
Content-Type: application/json
X-Correlation-Id: corr-...
```

```json
{
  "schemaVersion": "1.0",
  "correlationId": "corr-...",
  "workOrderId": "WO-20261109-001",
  "serialNumber": "SN-20261111-000001",
  "defectType": "SCRATCH",
  "confidence": 0.873,
  "imageId": "IMG-20261111-000001",
  "occurredAt": "2026-11-11T12:34:56.789Z"
}
```

成功响应：

```json
{ "schemaVersion": "1.0", "correlationId": "corr-...", "accepted": true, "mesOrderNo": "MES-20261111-0001" }
```

重复 SN 响应原单号并带 `duplicated: true`。

### 8.2 完工报工

```http
POST /mes/complete
Content-Type: application/json
X-Correlation-Id: corr-...
```

```json
{
  "schemaVersion": "1.0",
  "correlationId": "corr-...",
  "workOrderId": "WO-20261109-001",
  "inspectCount": 25,
  "okCount": 22,
  "ngCount": 3,
  "ngRate": 0.12
}
```

成功响应：

```json
{ "schemaVersion": "1.0", "correlationId": "corr-...", "accepted": true, "receiptNo": "RC-20261111-0001" }
```

### 8.3 错误分类

| 响应 | 处理 |
|---|---|
| 合法 2xx | 校验 schema、关联 ID、accepted 和业务号后写回 |
| 4xx（429 除外） | 立即死信，不重试 |
| 429 | 按 `Retry-After` 退避，超限死信 `MES_BUSY` |
| 5xx / 超时 | 1s/2s/4s 退避，超限死信 |
| 非法 2xx | 直接死信，例如 `INVALID_RESPONSE_SCHEMA` / `CORRELATION_MISMATCH` |

### 8.4 回执落地规则

回执按业务语义拆分：

- Node-RED 调用 `ns=2;s=QCStation.RecordMesReceipt`。
- NG 开单由 Method 写 `ns=2;s=QCStation.LastNgMesOrderNo`。
- 完工报工由 Method 写 `ns=2;s=QCStation.LastCompletionReceiptNo`。
- Method 同时写 `ns=2;s=QCStation.LastMesOrderNo` 作为最近回执的兼容镜像。

三者都不得覆盖 `CurrentWorkOrderId`。

## 9. 工单状态与事件的关系

```text
Idle --StartInspection(valid)--> Running
Running --same StartInspection--> Running (idempotent accepted)
Running --different StartInspection--> Running (rejected)
Running --CompleteWorkOrder(correct WO)--> Idle + WorkOrderCompletedEvent
Running --CompleteWorkOrder(wrong WO)--> Running (rejected)
```

关键不变量：

1. 一个时刻只有一个活动工单。
2. 拒绝的 Method 调用不得修改任何业务状态。
3. 完工事件只在成功调用 `CompleteWorkOrder` 后触发。
4. MES 回执写入不得改变当前工单。
