# 信息模型与业务规则速查

本文是 `Phase0_需求拆解与信息模型.md`、`M1_业务口径与MES契约.md` 和实际代码的对齐速查。写代码、联调、答辩前优先看这里。

## 1. 命名空间与 NodeId 规范

| 项 | 值 |
|---|---|
| NamespaceUri | `urn:fde:linqinspect:qc` |
| 常规 NamespaceIndex | `ns=2` |
| NodeId 风格 | `ns=2;s=<可读名>` |
| BrowseName 风格 | `2:<可读名>` |
| 安全策略 | 原型阶段 `NoSecurity`，生产必须加证书 |

示例：

```text
ns=2;s=QCStation
ns=2;s=QCStation.DeviceStatus
ns=2;s=QCStation.StartInspection
ns=2;s=NgDetectedEventType
```

## 2. 地址空间对象树

```text
Objects
└── QCStation
    ├── DeviceStatus              Int32 RW
    ├── CurrentWorkOrderId        String RW
    ├── CurrentPartSN             String RW
    ├── LastMesOrderNo            String RW（兼容镜像）
    ├── LastNgMesOrderNo          String RW
    ├── LastCompletionReceiptNo   String RW
    ├── StartInspection           Method
    ├── CompleteWorkOrder         Method
    ├── ResetCounters             Method
    ├── Inspection
    │   ├── LastResult            Boolean RO
    │   ├── LastDefectType        String RO
    │   ├── LastConfidence        Double RO
    │   ├── LastImageId           String RO
    │   ├── LastTimestamp         DateTime RO
    │   └── NgRate                Double RO
    ├── Statistics
    │   ├── InspectCount          UInt32 RO
    │   ├── OkCount               UInt32 RO
    │   └── NgCount               UInt32 RO
    └── Events                    Event Notifier
```

共 15 个变量：6 个根层读写变量、6 个 Inspection 只读变量、3 个 Statistics 只读变量。

## 3. 变量语义

| 变量 | 类型 | 权限 | 谁写 | 含义 |
|---|---|---|---|---|
| `DeviceStatus` | Int32 | RW | Method/测试工具 | `0=Idle`、`1=Running`、`2=Fault` |
| `CurrentWorkOrderId` | String | RW | `StartInspection`/`CompleteWorkOrder` | 当前派工工单 |
| `CurrentPartSN` | String | RW | 质检数据源 | 当前单件序列号 |
| `LastMesOrderNo` | String | RW | Node-RED | 最近一次 MES 回执的兼容镜像 |
| `LastNgMesOrderNo` | String | RW | Node-RED | 最近一次 NG 开单回执 `MES-*` |
| `LastCompletionReceiptNo` | String | RW | Node-RED | 最近一次完工报工回执 `RC-*` |
| `LastResult` | Boolean | RO | Server | `True=OK`、`False=NG` |
| `LastDefectType` | String | RO | Server | OK 时为空串；NG 时为缺陷码 |
| `LastConfidence` | Double | RO | Server | 0.0~1.0 |
| `LastImageId` | String | RO | Server | 图像/样本号 |
| `LastTimestamp` | DateTime | RO | Server | UTC 检测时间 |
| `NgRate` | Double | RO | Server | 滑动窗口 NG 率，空窗口 `-1.0` |
| `InspectCount` | UInt32 | RO | Server | 累计检测数 |
| `OkCount` | UInt32 | RO | Server | 累计 OK 数 |
| `NgCount` | UInt32 | RO | Server | 累计 NG 数 |

## 4. Method 契约

### 4.1 StartInspection

```text
输入: workOrderId:String, targetCount:UInt32
输出: accepted:Boolean, summary:String
```

| 前置条件 | 行为 |
|---|---|
| `workOrderId` 为空 | 拒绝：`empty workOrderId` |
| 正在 Running，且传入同一个工单 | 幂等接受：`already running` |
| 正在 Running，但传入不同工单 | 拒绝：`already running with different work order ...` |
| `DeviceStatus=Fault` | 拒绝：`DeviceStatus=Fault` |
| `targetCount<=0` | 拒绝：`targetCount must be > 0` |
| 合法且 Idle | 绑定工单，置 Running |

### 4.2 CompleteWorkOrder

```text
输入: workOrderId:String
输出: accepted:Boolean, summary:String
```

| 前置条件 | 行为 |
|---|---|
| 无活动工单 | 拒绝：`no active work order` |
| 传入工单与当前工单不一致 | 拒绝：`workOrderId mismatch, expected ...` |
| `DeviceStatus!=Running` | 拒绝：`DeviceStatus=... is not Running` |
| 全部通过 | 发 `WorkOrderCompletedEvent`；回 Idle；清空当前工单 |

成功后的 `summary` 包含：

```text
workOrder=<id> inspect=<n> ok=<n> ng=<n> ngRate=<x.xxx>
```

### 4.3 ResetCounters

清零累计统计和滑动窗口，并将 `NgRate` 恢复为 `-1.0`。

## 5. 事件模型

三个自定义 EventType 都继承 `BaseEventType`，通过 `QCStation.Events` 触发。

| EventType | 触发条件 | 自定义字段 |
|---|---|---|
| `InspectionFinishedEventType` | 每次检测完成 | WorkOrderId, SerialNumber, Result, DefectType, Confidence, ImageId |
| `NgDetectedEventType` | 每次检测为 NG | WorkOrderId, SerialNumber, DefectType, Confidence, ImageId |
| `WorkOrderCompletedEventType` | `CompleteWorkOrder` 成功 | WorkOrderId, InspectCount, OkCount, NgCount, NgRate |

注意事项：

- 客户端必须显式订阅具体 EventType；只订阅 `BaseEventType` 可能收不到自定义字段。
- `NgDetectedEventType` 是 Node-RED NG 开单的唯一事件来源。
- `WorkOrderCompletedEventType` 是 MES 报工的唯一事件来源。

## 6. 缺陷码

| 缺陷码 | 含义 | 默认严重度 |
|---|---|---|
| `SCRATCH` | 划痕 | 3 |
| `DENT` | 凹陷 | 3 |
| `STAIN` | 污渍 | 2 |
| `BURR` | 毛刺 | 3 |
| `MISSING` | 缺件 | 4 |

规则：全大写英文；OK 的 `LastDefectType` 必须为空串；新增缺陷码时同步修改 `server/qc_server.py` 的 `DEFECT_CODES` 与 M1 文档。

## 7. NgRate 滑动窗口

| 项 | 规则 |
|---|---|
| 窗口类型 | 按样本数的 FIFO 队列 |
| 默认大小 | 20 |
| 可配置 | `QC_NG_WINDOW` |
| 计算 | 窗口内 NG 数 / 窗口内样本数 |
| 空窗口 | `-1.0`，表示“无样本”，不是 0% |
| 报警阈值 | Node-RED 约定 `>=0.30` 且 `!=-1.0` |
| 累计统计 | `NgCount/InspectCount` 是整班次累计，不能与窗口率混用 |

独立 `NgRate` 变量和 `WorkOrderCompletedEventType.NgRate` 都遵守 `-1.0` 空窗口语义；MES 必须把 `-1.0` 解释为“样本不足”，不能当作 0% 不良率。

## 8. MES HTTP 契约

### 8.1 NG 开单

```http
POST /mes/ng-order
Content-Type: application/json
```

```json
{
  "workOrderId": "WO-20261109-001",
  "serialNumber": "SN-20261111-000001",
  "defectType": "SCRATCH",
  "confidence": 0.873,
  "imageId": "IMG-20261111-000001",
  "occurredAt": "2026-11-11T12:34:56.789Z"
}
```

成功响应：

```json
{ "accepted": true, "mesOrderNo": "MES-20261111-0001" }
```

重复 SN 响应原单号并带 `duplicated: true`。

### 8.2 完工报工

```http
POST /mes/complete
Content-Type: application/json
```

```json
{
  "workOrderId": "WO-20261109-001",
  "inspectCount": 25,
  "okCount": 22,
  "ngCount": 3,
  "ngRate": 0.12
}
```

成功响应：

```json
{ "accepted": true, "receiptNo": "RC-20261111-0001" }
```

### 8.3 回执落地规则

回执按业务语义拆分：

- NG 开单写 `ns=2;s=QCStation.LastNgMesOrderNo`
- 完工报工写 `ns=2;s=QCStation.LastCompletionReceiptNo`
- 同时写 `ns=2;s=QCStation.LastMesOrderNo` 作为最近回执的兼容镜像

三者都不得覆盖 `CurrentWorkOrderId`。

## 9. 工单状态与事件的关系

```text
Idle --StartInspection(valid)--> Running
Running --same StartInspection--> Running (idempotent accepted)
Running --different StartInspection--> Running (rejected)
Running --CompleteWorkOrder(correct WO)--> Idle + WorkOrderCompletedEvent
Running --CompleteWorkOrder(wrong WO)--> Running (rejected)
```

关键不变量：

1. 一个时刻只有一个活动工单。
2. 拒绝的 Method 调用不得修改任何业务状态。
3. 完工事件只在成功调用 `CompleteWorkOrder` 后触发。
4. MES 回执写入不得改变当前工单。
