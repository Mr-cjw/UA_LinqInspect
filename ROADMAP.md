# UA_LinqInspect Future Development Roadmap

> Analysis date: 2026-11-11  
> Scope: `server/qc_server.py`, `nodered/flows.json`, `.node-red/` runtime configuration, `tests/`, and project documentation.  
> Planning assumption: the project must serve both a portfolio-quality demonstration and a credible factory-pilot baseline. No production-grade claim should be made until the items in v1.x are complete.

## Current State

- **Maturity:** A well-documented and testable PoC+ / pre-pilot baseline, not a production system. The happy path, MES receipt split, retry/dead-letter behavior, and failure demos are strong; the latest documented results are M1 33/33, M2 10/10, and fault scenarios 19/19. M3 reconnect evidence and M4 delivery assembly remain incomplete.
- **Strongest assets:** A coherent OPC UA information model, explicit Method-based work-order control, clear separation between dispatch ID and MES receipt IDs, a stateful edge queue, simulated MES fault injection, and unusually good operational documentation for a prototype.
- **Biggest architectural shortcoming:** State has no single authoritative, transactional boundary. Work-order state lives in Python memory, the same state is exposed through writable UA variables, queue/deduplication state lives in Node-RED flow context, and MES receipt confirmation is a separate write-back step. This split-brain design causes bypass writes, race conditions, duplicate suppression errors, lost receipts, and inconsistent restart behavior.
- **Critical security debt:** The OPC UA endpoint uses `NoSecurity`, anonymous access, and `0.0.0.0`; Node-RED has no admin/HTTP authentication and exposes `/inject/*`; the simulated MES accepts unauthenticated payloads; and clients can directly write `DeviceStatus`, `CurrentWorkOrderId`, and MES receipt variables. The current setup is suitable only for an isolated lab.
- **Reliability debt:** Node-RED uses localfilesystem context with a one-second flush interval and no transaction. Deduplication is committed before enqueue, queue items are removed before receipt validation and UA write-back, queue overflow silently drops pending work, restart recovery of a non-empty queue is unverified, and the virtual serial-number sequence resets after process restart, which can create false duplicates.
- **Recovery debt:** OPC UA subscriptions are armed at deployment and re-sent five seconds later, but there is no subscription health state machine, monitored-item rebuild, event-gap detection, backlog reconciliation, or dead-letter replay workflow. A server restart can leave UA state, edge deduplication state, and in-flight work mutually inconsistent.
- **Concurrency and domain debt:** `StartInspection`, `CompleteWorkOrder`, and inspection recording do not share a lock. A completion can race with an in-flight inspection, producing late events or inconsistent snapshots. `targetCount` is advisory only, repeated work-order executions are not modeled as attempts, and completion at zero inspected parts is currently accepted.
- **Contract debt:** MES handling accepts any 2xx response as success without requiring `accepted: true`, a valid response schema, or matching idempotency payload. There is no `schemaVersion`, stable `errorCode`, `correlationId`, `429`/`Retry-After` policy, or distinction between retryable and business-terminal failures. The documented NgRate alarm rule is not implemented in the edge flow.
- **Operability and engineering debt:** `/qc/status` always reports `ok: true`; metrics, structured logs, event-drop counts, and subscription health are missing. Endpoints and ports are duplicated across Python and Node-RED, the Node-RED runtime directory is ignored by Git, dependencies are not reproducibly locked, function-node failures lack catch paths, and there is no CI, lint, type-check, or deterministic test harness.
- **Planning rule:** Delivery should be **at-least-once with idempotent consumers**, not advertised as exactly-once. Node-RED should remain an orchestrator and operator surface; durable delivery logic should move into a testable edge service as complexity grows.

## Short-term (v1.x)

1. **Secure the control plane and establish single-writer ownership (P0).** Bind the OPC UA server to loopback or a configured trusted interface; enable certificate trust and signed/encrypted sessions; make anonymous users read-only; require roles for Methods and write operations; make device status, current work order, and MES receipt variables externally read-only and writable only through controlled server methods or an authenticated MES gateway. Protect Node-RED with `adminAuth` and `httpNodeAuth`, run it behind HTTPS or localhost-only access, and move simulation injectors into a lab-only profile. **Exit criteria:** anonymous reads work, but anonymous writes, receipt forgery, and privileged Method calls are rejected; `/inject/*` is unavailable outside the lab profile; security regression tests cover these cases.

2. **Unify state and make inspection/work-order transitions concurrency-safe (P0).** Introduce one locked domain state machine for status, work order, attempt, counters, sliding window, and sequence generation; serialize `StartInspection`, `CompleteWorkOrder`, and `record_inspection` through the same state boundary; publish a versioned or snapshot-consistent view of statistics; validate SN, defect code, confidence, and OK/NG field consistency before accepting a result. Define whether completion requires the target count, how over-inspection is handled, and how a repeated work order becomes a new `attemptId`. **Exit criteria:** concurrent completion and inspection tests produce no late accepted results or mixed snapshots; zero-inspection completion follows the documented policy; repeated work orders have unambiguous idempotency keys; restart does not reset identity or counters silently.

3. **Replace file-context buffering with a durable outbox and explicit delivery states (P0).** Migrate queue, deduplication, dead letters, and receipt state to SQLite with WAL and transactions, or an equivalent local transactional store. Deduplicate and enqueue in one transaction; use unique constraints for NG and completion keys; add `PENDING`, `SENDING`, `RECEIPT_PENDING`, `UA_WRITE_PENDING`, and `DEAD` states; remove a task only after a valid MES receipt and confirmed UA write-back. Route queue overflow to a dead-letter record instead of silently dropping work, and provide an authenticated replay/acknowledge workflow. **Exit criteria:** forced process termination during enqueue, in-flight MES calls, and receipt write-back followed by restart causes neither loss nor duplicate business effects; dead letters are visible, replayable, and auditable.

4. **Harden the MES contract and end-to-end traceability (P1).** Add a generated or validated `correlationId` that follows the event from UA through queue, HTTP header, MES response, UA write-back, and logs. Add `schemaVersion: "1.0"` and stable error codes; validate JSON Schema, field types, lengths, ranges, and cross-field invariants; require `accepted: true` plus a valid receipt payload; treat `4xx` as terminal business failure, honor `429` and `Retry-After`, retry only timeouts and `5xx` with jittered backoff, and send malformed or ambiguous 2xx responses to the dead-letter path. **Exit criteria:** contract tests cover success, duplicate, invalid body, business rejection, `429`, `5xx`, timeout, empty 2xx, conflicting duplicate payload, and missing receipt; every business effect can be reconstructed from a correlation ID.

5. **Improve the operator workflow and delivery guardrails (P1).** Upgrade the status surface to show real health, queue age, in-flight tasks, retry counts, dead letters, MES latency, subscription state, event drops, and last successful heartbeat; add protected dead-letter listing, replay, and acknowledgement; make alarms recover explicitly; implement the documented NgRate threshold alarm or remove the contract claim. In parallel, provide deterministic fixtures and seedable virtual inspection, a one-command setup/test runner with teardown, and CI for Python syntax/tests, Node-RED function syntax checks, dependency locking, and documentation freshness. **Exit criteria:** an operator can diagnose and replay a failed task without opening the editor; CI is required for merges; tests are deterministic and clean up work orders, failure modes, and receipt variables.

## Mid-term (v2.0)

1. **Decouple the monolith into explicit domain and adapter modules.** Split the OPC UA server into a pure QC domain layer, an OPC UA address-space adapter, an inspection-source adapter for simulation or YOLO/ONNX, an event publisher, and configuration/validation. Extract queueing, retry, receipt handling, and dead-letter management from Function nodes into a dedicated edge sender service with unit-testable business rules; keep Node-RED for orchestration, visualization, and lab simulation. Introduce versioned internal interfaces so the server, edge sender, and MES gateway can evolve independently.

2. **Scale delivery with bounded concurrency, backpressure, and caching.** Replace the single-flight one-request-per-second pump with a bounded worker pool or partitioned dispatcher; preserve per-work-order ordering while allowing safe concurrency across independent work orders. Add rate limits, circuit breakers, jittered retries, queue-age SLOs, and explicit backpressure. Cache static information-model metadata, station configuration, and validated idempotency/receipt lookups with TTL and invalidation rules; never cache the authoritative work-order state. Use batching or consolidated writes for high-frequency UA statistics where the protocol and consumers allow it.

3. **Make the information model multi-station and standards-complete.** Introduce station identity, station registry, and per-station namespaces or nodes; add a proper `QCDeviceStatus` enumeration, attempt identifiers, explicit result and defect types, OPC UA Alarm & Condition objects for acknowledged alarms, and Historical Access or an external time-series/MQTT path for high-volume telemetry. Define model-version compatibility and a migration strategy for existing clients before changing NodeIds or event fields.

4. **Establish production operations and performance evidence.** Package services with systemd or containers, environment-based configuration, health/readiness probes, log rotation, backup/restore, and rollback instructions. Add Prometheus/OpenTelemetry metrics, structured JSON logs, correlation-ID search, and SLO dashboards. Run load, soak, restart, network-partition, MES-outage, and subscription-rebuild tests; publish measured throughput, event-to-MES latency, recovery time, backlog drain time, and zero-silent-loss evidence. Initial acceptance targets should be defined from the pilot’s real inspection cadence rather than assumed from the prototype.

## Long-term Vision

- **AI-native quality inspection:** Replace random simulation with a real YOLO/ONNX/TensorRT inference service, model registry, model-version and threshold lineage, confidence calibration, image retention policy, drift detection, false-positive/false-negative feedback, and active-learning loops. Every decision should remain attributable to an image, model version, threshold, and operator or automation action.
- **Semantic industrial agent layer:** Expose a narrow, policy-constrained MCP or tool API for read-only summaries first, then supervised actions such as work-order start, completion, replay, and maintenance workflows. The agent must reuse the same domain validation, role checks, and audit trail as human clients; it must never receive an unrestricted OPC UA write backdoor.
- **Fleet-scale quality platform:** Evolve from one simulated station into a multi-line, multi-site fleet with station onboarding, configuration distribution, centralized quality analytics, OPC UA for control semantics, and MQTT/Sparkplug B or event streaming for high-frequency data. Integrate real MES/SCADA/ERP systems while preserving dispatch-ID, attempt-ID, receipt, image, and serial-number lineage.
- **Autonomous, observable operations:** Combine digital-twin replay, chaos testing, subscription-gap detection, self-healing edge delivery, and human-approved remediation. The platform should detect a broken source, stalled queue, invalid model, or failing MES, contain the blast radius, and produce an actionable recovery plan without silently losing quality evidence.
- **Advanced CI/CD and factory delivery:** Add contract tests, simulation-in-the-loop and hardware-in-the-loop validation, signed artifacts and SBOMs, infrastructure-as-code, staged edge rollouts, canary deployment, automatic rollback, configuration drift detection, and disaster-recovery drills. The final delivery pipeline should be able to promote the same tested release from lab simulation to pilot hardware and then to production cells.
- **End state:** A secure, standards-based, AI-assisted industrial quality platform that closes the loop from inspection evidence to disposition, work order, MES receipt, audit, and continuous model improvement, while remaining safe to operate, easy to diagnose, and honest about its reliability guarantees.
